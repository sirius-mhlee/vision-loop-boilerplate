# vision-loop-boilerplate 구현 계획

## 1. 목표와 기본 구성

**로컬 이미지의 자동 라벨링 → 검수 → 데이터 버전 저장 → 학습 → 평가를 반복하고, 각 실험을 재현할 수 있는 프로젝트 기본 구성을 만든다.**

- **저장소 이름:** `vision-loop-boilerplate`
- **Python 패키지와 CLI:** `vloop`
- **저장소 설명:**

  > A boilerplate for an iterative computer vision pipeline covering auto-labeling, dataset versioning, training, and evaluation using FiftyOne, DVC, PyTorch, and MLflow

| 구성 요소 | 역할 | 보관하는 정보 |
|---|---|---|
| FiftyOne | 이미지 탐색, 자동 라벨링 실행 연동, 라벨 검수, 예측 분석 | 작업 중인 데이터와 라벨, 예측, 검수 상태 |
| SAM 3 | 클래스별 프롬프트를 이용한 자동 라벨링 | 객체별 박스·마스크·신뢰도 |
| Git + DVC | 검수한 데이터셋의 버전 관리와 복원 | 이미지, 정답 라벨, 클래스 매핑, 데이터 분할 |
| PyTorch + RF-DETR | 학습과 추론 | 학습 체크포인트와 모델 가중치 |
| MLflow | 실험 기록과 모델 보관 | 데이터·코드 버전, 설정, 지표, 모델, 실험 메모 |
| `vloop` | 위 구성 요소를 연결하는 명령어 | 단계별 실행 상태와 결과 식별자 |

첫 버전은 **현재 로컬 PC에서 이미지 폴더를 처리하는 방식**으로 구현한다. 예측 대상은 **객체별 박스와 마스크**, 학습 모델은 **RF-DETR Seg Nano**로 확정한다.

DINO 기반 데이터 선별, 동영상, CVAT·Label Studio 연동, 모델 서빙, 다중 사용자 작업 배정은 후속 범위로 둔다.

## 2. 실행 환경과 명령어

### 환경과 설정

- Python 3.12 가상환경을 사용한다. FiftyOne 1.21, RF-DETR 1.8.2, MLflow 3.16을 초기 호환성 확인 기준으로 삼고, 통합 검증을 통과한 의존성 전체와 SAM 3 코드 커밋을 고정한다.
- FiftyOne과 MLflow 화면은 localhost에 제공한다. FiftyOne의 작업 데이터베이스는 영속 저장하고, MLflow는 SQLite와 로컬 아티팩트 저장소를 사용한다.
- 자동 라벨링과 학습은 GPU를 공유하므로 순차 실행한다. Docker나 작업 스케줄러를 필수 구성으로 추가하지 않는다.
- 공통 설정은 `project.yaml`로 관리한다. 이미지 폴더, 클래스 ID·이름, 클래스별 SAM 3 프롬프트를 필수 입력으로 받고, 저장 위치·학습 설정·평가 설정도 함께 관리한다.
- 모든 명령은 공통 `--config` 옵션을 지원하며, 생략하면 현재 프로젝트의 설정 파일을 사용한다. 실행 당시의 최종 설정을 결과와 함께 저장한다.
- 실제 데이터 경로와 클래스는 사용자가 입력한다. 예시 클래스가 실제 데이터에 자동 적용되지 않도록 한다.

`vloop doctor`는 의존성, 저장 경로, GPU 접근, PyTorch CUDA 연산, 모델 체크포인트 접근을 확인한다. SAM 3는 공식 설치 요구사항과 체크포인트 접근 절차에 맞춰 준비한다. [SAM 3 공식 저장소](https://github.com/facebookresearch/sam3)

현재 도구 환경에서 GPU 접근은 확인되지 않았지만 커널 드라이버 로드는 확인됐다. **드라이버 수정 여부는 호스트의 `nvidia-smi`와 실제 CUDA 실행 결과를 확인한 뒤 판단한다.**

### CLI

| 명령어 | 동작 |
|---|---|
| `vloop doctor` | 실행 환경과 필수 설정 확인 |
| `vloop ingest` | 로컬 이미지 등록 |
| `vloop autolabel` | 새로운 자동 라벨링 작업 실행 |
| `vloop autolabel --resume <JOB_ID>` | 중단되거나 실패한 자동 라벨링 작업 재개 |
| `vloop review` | FiftyOne 검수 화면 열기 |
| `vloop release --version v001` | 검수 데이터를 고정하고 DVC 버전 생성 |
| `vloop train --dataset-version v001` | 지정한 데이터 버전으로 학습 |
| `vloop train --resume-run-id <RUN_ID>` | 저장된 마지막 체크포인트에서 학습 재개 |
| `vloop evaluate --run-id <RUN_ID> --dataset-version v001 --split val` | 지정한 모델과 데이터로 평가 |
| `vloop experiments` | MLflow 실험 화면 열기 |

평가의 기본 split은 `val`이다. 평가 데이터 버전을 생략하면 학습 실행에 기록된 데이터 버전을 사용하고, 선택된 버전을 출력한다. 최종 테스트는 `--split test`로 명시한다.

각 명령은 작업 ID, 사용한 데이터 버전, 성공·실패 건수와 결과 위치를 출력한다. 실패를 성공으로 표시하지 않으며 재개 가능한 식별자를 남긴다.

## 3. 단계별 구현

### A. 이미지 등록

- 입력 폴더를 재귀적으로 탐색하고 원본을 보존하면서 프로젝트 관리 저장소에 이미지를 등록한다.
- 파일 내용 해시를 식별자로 사용해 동일 파일의 재등록을 방지한다. 원본 경로와 등록된 이미지의 연결도 보관한다.
- 이미지 방향과 크기는 등록 단계에서 확정한다. 이후 라벨링·학습·평가는 동일한 이미지 좌표계를 사용한다.
- 손상되거나 지원하지 않는 파일은 원인과 함께 보고하고, 정상 파일 처리는 계속한다.
- 한 번에 전체 이미지를 메모리에 적재하지 않는다.

이 단계에서 수행하는 중복 확인은 **같은 파일의 반복 등록 방지**이며, DINO 기반 유사 이미지 선별은 포함하지 않는다.

### B. SAM 3 자동 라벨링

FiftyOne의 공식 `segment-anything-3-image-torch` 모델을 concept 모드로 사용한다. 설정한 클래스별 텍스트 프롬프트로 박스와 인스턴스 마스크를 생성하고, 출력 이름을 프로젝트의 클래스 ID에 연결한다. [FiftyOne SAM 3 연동](https://docs.voxel51.com/model_zoo/models/segment_anything_3_image_torch.html)

- 최초 배치는 1로 시작한다. 모델·프롬프트·임계값과 입력 이미지 목록을 작업 시작 시 고정한다.
- 예측 필드는 작업별로 분리하고 가중치 식별자, 설정, 작업 ID를 보관한다.
- 이미지별 상태를 저장해 완료된 이미지는 재처리하지 않고, 실패하거나 미완료인 이미지만 재개한다.
- 객체가 검출되지 않은 이미지도 정상적인 빈 예측으로 기록한다.
- 재개할 때는 원래 작업 설정을 사용한다. 프롬프트나 모델을 변경하면 새로운 작업으로 실행한다.
- 자동 예측은 검수 전까지 정답 라벨로 취급하지 않는다.

### C. FiftyOne 검수

FiftyOne의 기본 박스·마스크·클래스 편집 기능을 사용하고, 필요한 필드와 클래스 목록을 Annotation Schema에 등록한다. [FiftyOne 앱 내 라벨 편집](https://docs.voxel51.com/user_guide/annotation.html)

- 자동 예측을 보존한 채 검수용 `ground_truth`로 복사한다. 이미 사람이 수정한 라벨은 자동으로 덮어쓰지 않는다.
- 검수 상태는 **미검수 / 수정 중 / 완료 / 제외**로 관리하고, 상태별 저장 뷰를 제공한다.
- 객체가 없는 이미지도 사람이 확인한 후 완료 처리할 수 있다.
- 검수 완료와 재검수 전환은 작은 FiftyOne operator로 제공한다. 완료 시 라벨 내용의 해시를 기록하고, 릴리스 시 승인한 내용과 현재 내용이 일치하는지 확인한다.
- 완료 후 라벨이 변경됐다면 재검수가 필요하다. 자동 라벨링이나 일괄 내보내기가 검수 승인을 대신하지 않는다.

별도의 검수 웹 애플리케이션은 만들지 않고 FiftyOne 안에서 작업을 끝낸다.

### D. 데이터셋 릴리스와 DVC

**릴리스는 특정 시점에 승인된 이미지·정답·분할을 고정한 학습 입력이다.** 편집 중인 FiftyOne 데이터베이스와 분리한다.

- 검수 완료 상태이며 승인 내용이 일치하는 이미지만 COCO 형식으로 내보낸다.
- 객체가 없는 검수 완료 이미지는 포함하고, 미검수·제외 이미지는 포함하지 않는다.
- 마스크는 구멍과 분리된 영역을 보존하도록 COCO RLE로 저장한다. 선택한 RF-DETR 버전에서 실제 로딩과 마스크 보존을 검증한다.
- 클래스 ID, 클래스 이름, 이미지 ID, 검수 이력, 라벨 출처와 분할 목록을 함께 저장한다.
- RF-DETR의 COCO 디렉터리 구성에 맞추되, CLI의 `val`을 내보낸 데이터의 `valid`에 명시적으로 연결한다. [RF-DETR 데이터 형식](https://rfdetr.roboflow.com/1.8.2/learn/train/dataset-formats/)

분할 규칙은 다음과 같다.

- 최초 분할은 **train/val/test = 80/10/10, seed 42**로 한다.
- 촬영·장면 등의 그룹 정보가 있으면 같은 그룹이 서로 다른 split에 들어가지 않게 한다.
- 기존 이미지의 split은 유지한다. 새 이미지는 기본적으로 train에 넣되, 기존 val/test 그룹과 겹치면 자동 배정을 보류한다.
- 클래스별 표본 수와 빈 라벨 수를 보고한다. 정답이 없는 클래스의 평가 지표는 `N/A`로 구분한다.
- 검증·테스트 이미지나 정답이 바뀌면 해당 평가 데이터의 식별자도 바뀐다.

버전 생성과 복원 규칙은 다음과 같다.

- 내보낸 이미지와 라벨을 DVC로 추적하고, 관련 메타데이터를 Git 커밋과 `dataset/v001` 형태의 태그로 연결한다.
- 같은 버전 이름을 덮어쓰지 않는다. 내보내기 검증과 DVC remote 저장이 성공한 뒤 릴리스를 완료 처리한다.
- 초기 remote는 Git 저장소 밖의 로컬 폴더로 한다. Git에는 이미지·체크포인트·데이터베이스를 직접 넣지 않는다.
- 릴리스마다 별도의 전체 이미지 사본을 영구 보관하는 구조를 피하고, DVC의 콘텐츠 단위 저장을 이용한다.
- 과거 버전은 현재 Git 체크아웃과 검수 데이터를 바꾸지 않는 별도 캐시에 복원한다. 이미 복원한 버전은 재사용한다. [DVC 버전 지정 복원](https://doc.dvc.org/command-reference/get)
- 코드의 미커밋 변경을 데이터 릴리스 커밋에 자동으로 포함하지 않는다.

### E. 학습과 MLflow 기록

학습은 지정한 DVC 릴리스를 복원한 뒤 RF-DETR의 공식 학습 인터페이스로 실행한다. [RF-DETR 학습 문서](https://rfdetr.roboflow.com/1.8.2/learn/train/)

| 항목 | 초기값 |
|---|---|
| 모델 | 사전학습된 RF-DETR Seg Nano |
| 학습 횟수 | 30 epochs |
| Batch size | 1 |
| Gradient accumulation | 8 |
| Learning rate | `1e-4` |
| Seed | 42 |
| 입력 해상도·기타 설정 | 고정한 모델 버전의 기본값 |
| 최적 체크포인트 기준 | validation mask mAP |

- 학습 시작 시 MLflow run을 생성하고 실패·중단된 실행도 보존한다.
- 데이터 버전과 실제 Git 커밋·DVC 식별자, 학습 코드 커밋, 클래스 매핑, 전체 설정, 의존성 버전을 기록한다.
- 재현성을 위해 학습 코드가 커밋된 상태에서 실행한다. 실행 당시 설정은 별도 아티팩트로도 보관한다.
- 에포크별 손실과 검증 지표, 실험 목적과 관찰 메모를 남긴다.
- 최적 추론용 체크포인트와 마지막 학습 재개용 체크포인트를 구분한다.
- 학습 재개용 체크포인트에는 옵티마이저·스케줄러·에포크 상태를 포함한다.
- 재개 시 새로운 run을 만들고 원래 run ID를 연결한다. 데이터와 학습 설정을 원래 실행에서 복원해, 설정 변경 실험과 학습 재개를 구분한다.

MLflow 모델 아티팩트에는 **가중치, 모델 구성, 클래스 매핑, 전처리·후처리 설정**을 함께 저장한다. 추론은 현재 설정 파일의 모델 설정이 아닌 이 저장 내용을 기준으로 수행한다.

### F. 예측과 평가

- 학습 run ID로 모델을 새 프로세스에서 불러온다.
- 평가할 데이터 버전과 split을 명시적으로 읽는다. 학습 라이브러리의 기본 동작에 맡겨 다른 split이 사용되지 않게 한다.
- 고정된 정답을 별도 FiftyOne 평가 데이터셋에 적재하고, 평가 실행별 예측 필드와 평가 키를 생성한다.
- 박스와 마스크를 별도로 평가한다. 마스크 평가는 실제 마스크 IoU를 사용한다. [FiftyOne 객체·인스턴스 마스크 평가](https://docs.voxel51.com/user_guide/evaluation/detections.html)
- 박스·마스크의 COCO mAP, AP50, 클래스별 AP와 오탐·미탐 분석을 제공한다.
- mAP 계산에는 낮은 추론 임계값을 사용하고, 화면 표시용 임계값과 분리한다. 추론·평가 임계값과 최대 검출 수 등 지표에 영향을 주는 설정을 모두 기록한다.
- 예측 결과, 요약 지표, 평가 설정을 MLflow에 보관해 FiftyOne 화면을 다시 구성할 수 있게 한다.
- 평가 실행은 학습 run ID와 데이터 버전을 참조하는 별도 MLflow run으로 기록한다.

모델 비교 기준은 **동일한 평가 이미지·정답·클래스 매핑·평가 설정**이다. 이를 식별하는 해시를 저장한다. 학습 데이터가 `v001`에서 `v002`로 늘어나도 검증 데이터가 같다면 비교할 수 있다.

반복 개선에는 validation을 사용한다. test는 최종 평가에 사용하며, 테스트 결과를 반복적으로 보고 조정한 경우 새 최종 평가용 데이터가 필요하다.

## 4. 내부 구현 기준과 진행 순서

CLI는 실행 흐름을 담당하고, 이미지 등록·자동 라벨링·데이터 내보내기·학습·평가 로직은 독립된 모듈로 나눈다. 특정 모델의 교체가 데이터 버전 관리나 CLI 전체의 변경으로 이어지지 않게 한다.

도구 사이의 변환에는 **이미지 ID, 클래스 ID, 신뢰도, 원본 이미지 좌표의 박스, 인스턴스 마스크**를 담는 공통 표현을 사용한다.

- 프로젝트 클래스 ID와 모델 내부의 연속 인덱스 사이 매핑을 명시적으로 보관한다.
- FiftyOne의 정규화 좌표와 COCO·모델의 픽셀 좌표 변환을 한곳에서 처리한다.
- 마스크의 이미지 크기와 박스 위치를 검증한다. 변환 중 객체가 사라지거나 면적이 달라지는 문제를 테스트한다.
- DB, 모델 가중치, 대용량 이미지 등 실행 중 생성되는 자료는 코드와 분리해 저장한다.

구현은 작은 실제 이미지 묶음으로 다음 순서대로 진행한다.

| 순서 | 구현 내용 | 해당 단계의 확인 결과 |
|---|---|---|
| 1 | 환경·설정·CLI 기본 구조 | CUDA 연산과 SAM 3 한 장 추론 성공 |
| 2 | 이미지 등록·자동 라벨링 | 중복 없는 등록과 중단 후 재개 |
| 3 | FiftyOne 검수 | 라벨 수정·승인·재검수 동작 |
| 4 | COCO·DVC 릴리스 | `v001` 생성과 별도 폴더 복원 |
| 5 | 학습·MLflow | 실제 짧은 학습, 기록, 체크포인트 재개 |
| 6 | 모델 복원·평가 | run ID 기반 추론과 FiftyOne 결과 확인 |
| 7 | 반복 개선 | `v002` 학습 및 동일 검증 데이터에서 비교 |

환경 준비, 필수 설정 작성, 첫 실행, 오류 복구, 데이터 버전 복원 절차를 문서화한다. 전체 데이터 처리는 작은 묶음의 모든 단계를 통과한 뒤 수행한다.

## 5. 검증과 완료 기준

### 핵심 테스트

- 같은 이미지를 여러 번 등록해도 중복이 생기지 않는다.
- 자동 라벨링 중단 후 재개해도 기존 완료 결과와 사람의 수정 내용이 보존된다.
- 빈 예측, 추론 실패, 검수 완료된 빈 정답을 서로 구분한다.
- 검수 승인 이후 라벨을 변경하면 재승인 없이 릴리스할 수 없다.
- COCO 변환 전후에 클래스·박스·마스크가 일치한다. 비정방형 이미지와 구멍·분리 영역이 있는 마스크를 포함한다.
- RF-DETR이 내보낸 RLE 라벨을 실제 학습 입력으로 읽는다.
- split 사이에 동일 이미지와 지정된 그룹이 섞이지 않는다.
- 별도 작업 폴더에서 동일한 이미지·정답·분할을 복원하고, 현재 검수 데이터는 유지된다.
- 짧은 실제 GPU 학습으로 MLflow 기록과 체크포인트를 만들고 재개한다.
- 새로운 프로세스에서 MLflow run ID만으로 모델을 복원해 추론한다.
- 정답과 일치하는 예측, 잘못된 예측, 빈 예측으로 박스·마스크 평가의 동작을 확인한다.
- `v001 → 수정 → v002`를 수행해도 이전 데이터·모델·평가 결과가 남아 있다.

### 완료 기준

실제 데이터로 **자동 라벨링부터 평가까지 두 차례의 개선 과정을 완료**하고, 다음 정보를 연결해서 확인할 수 있어야 한다.

> 이 모델은 어떤 코드와 설정으로, 어떤 데이터 버전에서 학습됐으며, 어떤 평가 데이터에서 어떤 결과를 냈는가?

목표 정확도는 첫 기준 모델의 클래스별 결과를 확인한 뒤 정한다. 첫 구현의 성공 기준은 **작동하는 전체 흐름, 사람의 검수 반영, 데이터와 실험의 추적 가능성, 저장 결과의 복원 가능성**이다.
