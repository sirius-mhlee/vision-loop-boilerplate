  비교해 통과했습니다. 장치 compute capability는 12.0입니다.

- NumPy 1.26.4, OpenCV headless 4.11.0.86, SciPy 1.16.3, tifffile 2025.5.10,
  einops 0.8.2, pycocotools 2.0.11 조합을 설치하고 `autolabel` extra에 기록했습니다.

- 실제 데이터 폴더·클래스·프롬프트는 미입력 상태입니다. 검증에는 별도 설정과 SAM 3 공식

## 자동 라벨링 구현

- `vloop autolabel [--limit N]`, `vloop autolabel --resume JOB_ID`를 추가했습니다.
- 작업별 SQLite 입력·상태 목록, 최종 설정, SAM 3 커밋·체크포인트·어휘·adapter·의존성 해시를
  보관합니다. 재개에는 원래 설정을 사용하며 완료 결과를 다시 추론하지 않습니다.
- 예측 JSON을 먼저 저장한 뒤 FiftyOne에 반영합니다. DB 쓰기만 실패한 이미지는 추론 결과를
  재사용합니다. 처리 상태와 정상 빈 예측을 구분하고 실패한 이미지의 원인을 남깁니다.
- 예측 필드는 작업별로 만들며 `ground_truth`와 검수 상태를 수정하지 않습니다.
- 공통 표현에 클래스 ID, 프롬프트, 신뢰도, 픽셀 박스, 전체 이미지 크기의 COCO RLE를
  저장합니다. FiftyOne의 박스 내부 마스크와 변환할 때 크기·좌표·면적을 검사합니다.
- 8 GB 환경을 위해 이미지·프롬프트를 하나씩 처리하고 BF16을 사용합니다. 모델은 작업 중
  재사용하며 컴파일은 끕니다. FiftyOne 1.21의 내부 점수 필터도 사용자 임계값에 맞춥니다.

## FiftyOne 검수 구현

- `vloop review [--job-id JOB_ID] [--prepare-only] [--no-browser]`를 추가했습니다.
  기본값은 가장 최근 등록된 자동 라벨링 작업입니다. 실행 기록에 선택한 작업과 초기화·보존·
  예측 없음·승인 무효화 건수를 남깁니다.
- 검증한 예측 JSON에서 새 라벨 ID로 `ground_truth`를 초기화합니다. 기존 수동 정답과 검수
  이력을 보존하고, 검수용 정답을 나중에 삭제해도 자동 예측으로 덮어쓰지 않습니다.
- 클래스 선택·마스크 수정을 위한 Annotation Schema, 읽기 전용 예측 필드, 미검수·수정 중·
  완료·제외 저장 뷰를 만듭니다. Python 검수 operator는 프로젝트 저장소 안에 설치합니다.
- 열린 이미지 또는 직접 선택한 이미지에 검수 시작/재검수·완료·제외를 적용합니다.
  완료 시 확인 체크와 검수자 이름이 필요하며, 빈 정답은 객체가 없다는 별도 확인을 요구합니다.
- 승인 시 정답 스냅샷·해시·출처·검수자·시간을 JSON과 DB 이력에 남깁니다. 승인과 동시에
  마스크가 수정되면 조건부 DB 갱신이 실패하도록 하여 편집 내용을 덮어쓰지 않습니다.
- 네이티브 브러시가 화면 해상도의 마스크와 소수 박스를 저장하는 것을 확인했습니다.
  승인 시 원본 픽셀 경계를 반올림하고 nearest-neighbor로 전체 이미지 RLE를 만듭니다.
  편집 원본의 박스·마스크 RLE도 별도로 보존합니다.
- 서버는 인덱스와 저장한 조회 위치로 DB 수정 내역을 따라갑니다. 기본 5초마다 최대
  10,000건의 메타데이터를 스트리밍으로 읽고 변경된 승인 최대 100건만 검사합니다.
  외부 이미지·기록 파일을 포함하는 전체 검사는 `review-audit`로 따로 실행합니다.
  후속 릴리스용 `approved_annotation()`은 기본적으로 수동 승인만 허용합니다.
- FiftyOne 1.21의 펼친 이미지 상태 표시는 operator의 reload 요청 후에도 이전 값이 남는
  경우가 있습니다. DB 변경은 성공하며 브라우저 새로고침 후 최신 상태가 보입니다.
  실제 대규모 DB·이미지 처리 성능은 후속 확인 대상입니다.

## 100만 장 이상을 위한 검수 보완

- `review-batch`로 작업 ID·최소 신뢰도·검수 표본 비율·정책 선택자를 지정합니다.
  먼저 채택·표본·낮은 신뢰도·빈 예측·보존·오류 건수를 미리 계산하고, 그 작업 ID에
  `--resume ID --apply`를 실행해 적용합니다. 구현 검증 중 실제 사용자 데이터에 적용하지 않았습니다.
- 일괄 채택은 `auto_accepted`/`automatic`, 수동 승인은 `completed`/`manual`로 구분합니다.
  자동 채택을 후속 릴리스에 포함하려면 `allow_auto=True`를 명시해야 합니다.
- 낮은 신뢰도·빈 예측·무작위 표본을 각각 저장 뷰로 제공합니다. 높은 신뢰도의 표본은
  이미지 ID·seed로 결정하므로 배치 크기와 재개 시점이 달라도 유지됩니다.
- 대상 ID·예측 해시·수정 시점을 SQLite 스냅샷으로 고정하고, 기준이나 스냅샷이 변경되면
  재개를 거부합니다. 메모리에는 기본 100개 ID와 처리 중인 이미지의 라벨만 유지합니다.
- 중단한 미리보기·적용을 이어갈 수 있습니다. DB 저장 성공 후 진행 기록이 남기 전에
  중단된 경우도 복구하며 같은 배치로 재승인하지 않습니다. 수동 수정이 있으면 보존합니다.
- 자동 채택 스냅샷은 `reviews/records.sqlite3`에 모아 새 JSON 파일 100만 개를 만들지 않습니다.
  수동 승인·재검수 이력과 원본 자동 예측은 보존합니다.
- 화면 시작 시 정답 초기화는 기본 100장으로 제한합니다. 검수 목록의 나머지 마스크는
  필요할 때 초기화합니다. 수동 operator도 최대 100장으로 제한하고 대량 작업은 CLI로 처리합니다.
- 전체 무결성 검사에는 `review-audit [--resume ID]`를 사용합니다. 증분 검사는
  수정 시점을 갱신하지 않는 직접 DB 조작·외부 파일 변경을 대신 확인하지 않습니다.
- 이는 검수 단계의 메모리·반복 조회·파일 수를 보완한 것입니다. 기존 ingest/autolabel의
  전체 해시 검사, 이미지별 JSON·PNG 저장, 실제 모델 처리량과 MongoDB 디스크 사용량까지
  100만 장의 실제 데이터로 검증한 것은 아닙니다.

## 검증 결과

- 기본 테스트 97개 통과. 실제 DB·GPU 테스트 4개는 기본 실행에서 명시적으로 제외합니다.
- 별도 호스트 실행에서 FiftyOne 통합 테스트 3개 통과: 실제 등록, 다른 프로세스의 재등록,
  중복 방지, `ground_truth`와 검수 상태 보존, 예측 필드 생성 도중 중단된 상태의 복구를 확인했습니다.
- 검수 통합 테스트는 정답 복사·삭제 후 보존, 승인·마스크 변경 감지·재승인·제외,
  빈 정답과 예측 없음의 구분, 클래스 수정 후 ID 매핑, 동시 수정 충돌, 플러그인 등록을 확인합니다.
  기본 테스트는 마스크 좌표 변환과 승인 기록·이미지 변경 및 상태 문자열만의 승인 우회를 검사합니다.
- 일괄 채택 테스트는 미리보기·적용 중단, 새 프로세스에서 DB 저장 직후 중단 복구,
  수정 내용 보존, 표본 목록과 제한된 초기화, 자동 채택의 명시적 허용, 변경 없는 승인의
  해시 검사 생략, 수정 후 무효화, 전체 이미지 검사와 정책 변경 거부를 확인했습니다.

  측정값이 아닙니다. 검증 기록은 `.vloop/review-scale.json`에 있습니다.

  검수 완료를 실행했습니다. 화면 해상도의 마스크도 재승인됐고, 다시 수정하면 승인 해시가
  제거되고 `Ground truth changed after approval` 사유로 수정 중 상태가 됐습니다.
  자동 예측 JSON의 해시는 유지됐습니다. 이는 별도 데모의 기능 검증이며 실제 데이터 승인이 아닙니다.

  결과 재사용, 설정·입력·결과 변경 감지, 스냅샷 생성 중 중단의 복구 안내를 테스트했습니다.

  실패는 RF-DETR·MLflow·DVC 미설치이며 `sam3_inference`는 통과했습니다.
  실제 `project.yaml`은 데이터·클래스가 비어 있어 필수 입력 검사도 아직 통과하지 못합니다.
